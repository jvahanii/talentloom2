## Goal

Rip out the top nav + page-based shell. The whole authenticated app becomes one **agentic workspace**: a centered command prompt, a scrollable "thread" of past exchanges, and a live **viewport** in the middle that dynamically constructs UI modules in response to intent. No persistent sidebar, no dashboard grid.

## What the workspace looks like

```text
 ┌───────────────────────────────────────────────────────────┐
 │  Talently · workspace                            you ▾    │  ← minimal top bar (brand + user menu only)
 ├───────────────────────────────────────────────────────────┤
 │                                                           │
 │   [ thread of past turns — user intent + module cards ]   │  ← scrollable flow
 │                                                           │
 │   ┌─ candidate card ───────────────────┐                  │
 │   │ Ada Lovelace · Interview           │                  │  ← modules morph in with
 │   │ [Move to Offer] [Reject] [Notes ▾] │                     framer-motion layout
 │   └────────────────────────────────────┘                  │
 │                                                           │
 │   ┌─ pipeline graph ───────────────────┐                  │
 │   │ (interactive stage nodes)          │                  │
 │   └────────────────────────────────────┘                  │
 │                                                           │
 ├───────────────────────────────────────────────────────────┤
 │  ▍ Ask or type / for commands…                       ⏎    │  ← sticky agent prompt
 └───────────────────────────────────────────────────────────┘
```

Only two chrome elements survive: a minimal top bar (brand + sign-out menu) and the sticky prompt. Everything else is generated by the agent.

## Intent resolution — hybrid

1. **Slash commands** run locally, instantly, no model call:
   - `/candidate <name>` → candidate mini-card + stage sheet
   - `/req [title]` → requisition editor panel (new or edit)
   - `/pipeline` → interactive graph node view
   - `/funnel`, `/sources`, `/time-in-stage` → analytics chart card
   - `/help` → command palette module
2. **Free-text fallback** posts to a server function that calls `google/gemini-3-flash-preview` via the Lovable AI Gateway with an `Output.object` schema returning `{ module: "candidate" | "requisition" | "graph" | "analytics" | "text", args: {...}, reply: string }`. The client renders the module + assistant text.
3. Every resolved intent is appended to the workspace thread as a `Turn` record (user utterance + module spec + optional assistant text).

## Modules the viewport can construct

| Module | Trigger | What it renders |
| --- | --- | --- |
| `CandidateCard` | `/candidate`, "show <name>", "move <name> to <stage>" | Avatar, name, requisition, stage badge, inline **stage sheet** (segmented control of stages, notes field, save) |
| `RequisitionPanel` | `/req`, "create a role", "edit <title>" | Inline form: title, department, hiring manager, status, target start, notes |
| `PipelineGraph` | `/pipeline`, "show the pipeline" | SVG graph of the 7 stages as nodes; edges = candidate flow; node size scales with count; click node → filter candidates below |
| `AnalyticsCard` | `/funnel`, `/sources`, `/time-in-stage`, "how are we doing" | The matching Recharts chart in a glass module |
| `TextTurn` | any fallback with no module | Plain assistant reply rendered as markdown |

Each module is a small React component; the viewport is a `<AnimatePresence>` list keyed by turn id.

## Motion (level 4)

Framer-motion with **shared-element layout morphs**:

- New modules mount with `layout` + `initial={{ opacity: 0, y: 12, scale: 0.98 }}` → `animate` spring (stiffness ~260, damping ~28).
- Stage badges use `layoutId={"stage-" + candidateId}` so moving a candidate makes the badge fly from card to graph node.
- Prompt bar uses `layout` so it grows/shrinks smoothly as the composer height changes.
- Thread reflows via `<motion.div layout>` wrappers so inserting a new module pushes older ones with an elastic ease instead of a jump.
- Graph nodes: `whileHover={{ scale: 1.05 }}`, connecting edges animated with `pathLength` on mount.

## Data flow

- Workspace state lives in-component (`useState<Turn[]>`); nothing persisted server-side. Refresh = fresh workspace (matches the "no dashboard" ethos).
- Each module reads live Supabase data through the existing TanStack Query keys (`candidates`, `reqs`, `stage-history`), so mutations from a card invalidate and re-render across the thread automatically.
- Server function `resolveIntent` requires auth (uses `requireSupabaseAuth` middleware) and only returns the module spec + reply — no database work happens in the model call.

## Dependencies

- Add `framer-motion` (`bun add framer-motion`). Everything else already exists (`ai`, `@ai-sdk/openai-compatible`, `zod`, `recharts`, Supabase client).

## Technical notes

- The `resolveIntent` server function uses `generateText` with `Output.object` and a **small** schema (`module: z.enum(...)`, `args: z.record(z.string(), z.any()).optional()`, `reply: z.string()`) — no `.min/.max` bounds, per the AI SDK gateway rules; the prompt states the limits, code clamps.
- Middleware wiring for `requireSupabaseAuth` is already present in `src/start.ts`.
- Deep routes stay under `_authenticated` so RLS + auth guard behavior is unchanged.
- The AI fallback is only called when input doesn't match a slash command; slash usage costs nothing.
- Accessibility carried forward: the prompt input keeps focus by default, every module button has a real label, focus-visible outlines remain.

## Known limits & follow-ups (called out in the reply, not built)

- Turns are session-only; a follow-up could persist them per-user.
- The AI fallback is single-shot (no tool loop). Multi-step ("find Ada then move her to offer") would need `stepCountIs(50)` + tools.
- The graph is SVG with fixed layout; a force-directed layout could come later.
